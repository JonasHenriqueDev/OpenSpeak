# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

OpenSpeak is a P2P video streaming app (screen/window/camera with audio) modeled on TeamSpeak 6's streaming engine and UI. Docs, comments, changelog and UI strings are in Portuguese (pt-BR); keep new ones in Portuguese. Analysis of the original TS client: `docs/ANALISE_TEAMSPEAK_P2P.md`.

## Two implementations, one protocol

1. **Web client + Node server** (repo root): `server/` (signaling, `virtualServer.js`), `public/js/` (browser WebRTC client; phones and tablets get the watch-only `ui/MobileApp.js`, `?mobile=1` forces it), `api/` + `vercel.json` (Vercel deployment: `/ws` → `api/ws.js`, with `server/cloudRoom.js` + `redisRoomStore.js` for room state).
2. **Native Windows app** (`native/`, C++ / Qt 6 QML / libdatachannel / FFmpeg+NVENC): client `OpenSpeak.exe` (`native/client/`) and server `openspeak-server.exe` (`native/server/`). Shared wire protocol in `native/common/Protocol.h`.

Native and browser clients speak the **same protocol** and can watch each other — a protocol change must be mirrored in `server/protocol.js`/`server/virtualServer.js` and `native/common/Protocol.h`/`native/server/VirtualServer.cpp`.

Command names deliberately match TeamSpeak 6 (`setupstream`, `joinstreamrequest`, `respondjoinstreamrequest`, `streamsignaling`). Flow: streamer `setupstream` → viewer `joinstreamrequest` (with decodable codecs) → privacy check (Public/Contacts/Private) → streamer creates a `SessionOutbound` and offers → SDP/ICE over `streamsignaling` → media peer-to-peer (DTLS-SRTP). Class names mirror TS too: `ScreenshareManager`, `StreamBase`, `SessionOutbound`/`SessionInbound`, `StatsCollector` (same thresholds as TS).

The native server additionally implements SFU mode (`STREAM_SFU`): `native/server/Sfu*.cpp` (ingest, forwarder, egress, relay, and a WebSocket viewer fallback `SfuWsViewer`). The web server only announces `STREAM_P2P`. SFU simulcast (capability `STREAM_SFU_SIMULCAST`): the native streamer sends a second, low video layer (m-line mid `video-low`, own encoder); `Forwarder` picks a layer per viewer and switches only on a keyframe, rewriting seq/timestamp per viewer; `SfuLayerPolicy.h` is the auto rule. Viewers choose auto/high/low with `streamsignaling` `{type:'layer', preference}` to clid 0, and the relay reports `{type:'layer', simulcast, layer, preference}` back.

Drawing (capability `STREAM_DRAW`, both servers, not the tailnet mesh): accepted viewers send `streamdraw` {action:'stroke', stroke, color, width, points:[x,y,...] in 0..10000 of the video frame, end} or {action:'clear'}; the server validates, rate-limits (30/s) and relays `notifystreamdraw` only to the *other* viewers, never to the streamer. No history: late joiners see only new strokes; each point fades on the client (6 s solid + 4 s fade, oldest first); clients drop an author's strokes when they leave `notifystreamattendees`. Client logic: `ScreenshareManager::drawTo/onDraw` + `qml/DrawingLayer.qml` (native), `public/js/video/drawings.js` (web); hiding is the `showDrawings` setting.

Profiles (capability `PROFILES`, not on the Vercel room): a nickname becomes a profile when it gets a password (`setprofilepassword`); `login` then requires `profilePassword`, and `updateprofile` edits display name, color, description and avatar, which go out in `publicClient`. Heavy media (capability `PROFILE_MEDIA`: banner and the GIF `avatarAnimated`, whose first frame is the static `avatar`) stays out of `publicClient`, which only carries `mediaTag`; clients fetch it with `profilemedia` when a card opens and cache by tag. Stored in a JSON file shared by `server/profileStore.js` and `native/server/ProfileStore.cpp` (`OPENSPEAK_PROFILES_FILE`).

## Commands

Web/Node:
```bash
npm install
npm start                               # http://localhost:9988 ; ?profile=a&debug for a 2nd profile + test-pattern source
npm test                                # node --test "test/*.test.js"
node --test test/server.test.js         # single test file
```
Env: `PORT`, `HOST`, `OPENSPEAK_NAME`, `OPENSPEAK_PROFILES_FILE`, `OPENSPEAK_ICE` (JSON iceServers), `OPENSPEAK_CERT`/`OPENSPEAK_KEY` (HTTPS, needed off-localhost for capture).

Native (Windows, PowerShell; toolchain paths are hardcoded defaults in the scripts: VS 2026, Qt `C:\Qt\6.11.3\msvc2022_64`, vcpkg `D:\Dev\vcpkg`, triplet `x64-windows-static-md`, deps in `native/vcpkg_installed`):
```bash
powershell -ExecutionPolicy Bypass -File native/build.ps1               # Release build (Ninja) + only the tests whose inputs changed
powershell -ExecutionPolicy Bypass -File native/build.ps1 -AllTests     # same, full suite
powershell -ExecutionPolicy Bypass -File native/build.ps1 -DryRun       # print the test selection, build nothing
powershell -ExecutionPolicy Bypass -File native/build.ps1 -ServerOnly   # server + tests only
powershell -ExecutionPolicy Bypass -File native/build.ps1 -Tests 'tst_engine|ui_'   # force tests by ctest -R regex
powershell -ExecutionPolicy Bypass -File native/package.ps1             # Lite installer only (default) into native/dist
powershell -ExecutionPolicy Bypass -File native/package.ps1 -Full -Portable   # also Full edition and portable ZIP/exe
```
**Packaging rule (user preference):** build/package **only the Lite installer** (plain `package.ps1`, no flags). Do **not** pass `-Full` or `-Portable` unless the user explicitly asks for the Full edition or the portable builds in that request. When publishing a Lite-only release, upload just `OpenSpeak-Setup-<versão>.exe`, `OpenSpeak-Setup.exe` and the `SHA256SUMS-<versão>.txt` covering them.
Test selection lives in `native/tests/TestSelection.ps1`: each test lists its input files, and `build.ps1` runs it only if their hash differs from its last pass (`build/test-cache-<Config>.json`; a failed test stays pending). Unmapped files and tests fall back to running everything, so add new ones to the map. `build.ps1` builds only the test executables it will run, plus `OpenSpeak` and `openspeak-server`; tests run with `ctest --parallel 8` (`RUN_SERIAL` for real-window tests, `RESOURCE_LOCK e2e` for e2e). `package.ps1` uses the same selection; pass `-AllTests` to force the full suite.
Single native test: `ctest --test-dir native/build -C Release -R tst_virtualserver --output-on-failure` (Qt `bin` must be on PATH). Tests: `tst_virtualserver`, `tst_windowthumbnail`, and `ui_<panel>` smoke tests that run `OpenSpeak --ui-smoke-test --open <panel>`.

## Releases / editions

- Version is set in **both** `native/build.ps1` and `native/package.ps1` (`-Version` default) and passed to CMake as `OPENSPEAK_RELEASE_VERSION`, which only feeds the generated `build/generated/Version.cpp` (`native/common/Version.cpp.in` → `openspeak::version()` in `common/Version.h`; never reintroduce a version compile definition, so a version bump only recompiles that file + relinks); add a `native/CHANGELOG.md` entry per release. Installer script: `native/installer/OpenSpeak.iss` (Inno Setup 6).
- Two editions share one `OpenSpeak.exe`; `edition.txt` selects it. **Lite** (default, `OpenSpeak-Setup.exe`): server client only (P2P or SFU). **Full** (`OpenSpeak-Full-Setup.exe`): adds Tailnet mode, web room and the dedicated server. Auto-update logic: `native/client/core/AutoUpdater.*`, `UpdatePolicy.*`; see `docs/ATUALIZACOES.md`.

## Production / monitoring

Default server `wss://openspeak.duckdns.org/ws` runs the native server on an Oracle VM behind Caddy. `monitor/` is a stdlib-only Python dashboard (`monitor.py`, tests in `monitor/test_monitor.py`) reading the snapshot the native server writes when `OPENSPEAK_METRICS_FILE` is set; it listens on `127.0.0.1:9990` only and must not be exposed. Snapshot fields (IPs, User-Agent, etc.) must never be added to the public room list.

`discord-bot/` is a standalone Node bot (own `package.json`, `npm test` there) that polls `GET /api/live` (both servers: `liveSnapshot()`) and announces live streams in a voice channel status, a text channel and its presence. With nobody live, the presence rotates `PRESENCE_TIPS` (`src/live.js`: usage examples, `presence.tips`/`tipSeconds`, shown even with the live status off). Streams carry `announce` (default true, "Mostrar ao vivo no bot do Discord" in the advanced stream settings) and `app` (native client: window's program name); `/api/live` must only expose public fields. With `OPENSPEAK_LIVE_WEBHOOK` (+ `_SECRET`) the servers also POST that snapshot to the bot when it changes (VirtualServer live-changed callback, debounced 300 ms). Bot notices are per Discord server (`state.json` `guilds`: chat channel/mention, voice status, links; `guildNotices`/`migrateSettings` in `src/live.js`), except the bot's presence, which is global (app owner only). The bot is called Frisquila. Settings are edited in a button/select panel (`/painel`, rendered by `src/panel.js`, component customIds `os:*`; `/links` is the per-user panel). The bot also fixes X/Twitter, TikTok (→ tnktok.com) and Instagram reels/posts (→ uuinstagram.com) links (`src/xlinks.js`, networks chosen per server in the panel): per Discord server, off by default, scope "usuarios" (only users who opted in with `/links`, default) or "todos" (everyone except opt-outs), mode "responder" (suppress embed + reply, default) or "substituir" (delete + resend via webhook as the author); needs the privileged Message Content Intent, and falls back to connecting without it. Deadlock commands (`/build`, `/counter`, `/heroi`) use the public deadlock-api.com (`src/deadlock.js` data + ranking, `src/dlview.js` embeds, `src/buildcode.js` encodes the in-game build code: base64(zstd(protobuf CMsgHeroBuild)), verified byte-for-byte against a game export; per Discord server their replies are public by default or ephemeral (`/painel` → Deadlock, `state.json` `guilds.<id>.deadlock.ephemeral`, also applies to `/frisquila pergunta:`; the counter-items screen's "🧠 Por quê?" button asks ia-gateway to tie 3–4 items from a closed candidate list to the hero's official ability texts, `counterCandidates`/`parseCounterReasons` in `src/ask.js`; `@Frisquila` answers are plain messages and stay public); `src/buildimage.js` draws the item grid PNG with @napi-rs/canvas and the bundled Noto Sans). "Item bom contra X" (or against one ability: `findAbilityInText`, "ult do lash") gets a conversational answer (`counterChat` in `bot.js`, `counterAnswerMessages`/`parseCounterAnswer`, `renderCounterAnswer`): the AI ranks items only from `counterCandidates`, ending with "se eu tivesse que escolher só um"; falls back to the stats screen. Open questions and that answer also use web search (`searchGateway` → ia-gateway `POST /v1/pesquisa`: Groq gpt-oss + browser_search on the free tier, Gemini google_search as paid fallback; a daily token budget `pesquisa.max_tokens_dia` because each search costs 15–45k tokens; the bot caches counter searches 6 h per hero+ability; sources shown under the answer; failure = official data only). AI answers are cached in `cache.json` (`src/answercache.js`, `OPENSPEAK_BOT_CACHE`): counter answers by hero+ability+rank (6 h), open questions/OpenSpeak/web searches by their important words, also reused for similar questions (Jaccard ≥ 0.8, same hero/item, ≥ 3 words). Free questions (`@Frisquila …`, `src/ask.js`) are parsed locally first and otherwise classified by the separate ia-gateway service (task `frisquila`, repo JonasHenriqueDev/ia-gateway, 127.0.0.1:8092 on the VM); Deadlock trivia the game doesn't answer (e.g. "o Viscous é casado?") gets a joke that asserts nothing. They also cover OpenSpeak (`src/openspeak.js`): questions are answered only from the hand-written `OPENSPEAK_FACTS` plus the live `native/CHANGELOG.md` from GitHub (keep `OPENSPEAK_FACTS` current when app features change), and bug reports/suggestions become a draft the reporter confirms with buttons (customIds `is:*`) before the bot opens a GitHub issue labelled `frisquila` (+ `bug`/`enhancement`) or comments on an open duplicate; token in `GITHUB_TOKEN` or config `github.token` (fine-grained, Issues read/write), 3 reports per user per 24 h, the issue quotes the reporter's Discord display name only.

Logs (capability `CLIENT_LOGS`, both servers when `OPENSPEAK_LOG_DIR` isn't "off"; default `logs/` in the user data dir, `~/.openspeak/logs` for Node): the server writes its own log to `server-<dia>.log` and what clients send with `clientlog` {version, lines} to `clients/<dia>/<apelido>.log` (`native/server/LogStore.*`, `server/logStore.js`: 500 lines per command, 8 MB per client per day, 14 days). The native client (`native/client/core/ClientLog.*`) installs the Qt message handler, keeps a local file per day (7 days, "Abrir pasta de registros" in settings) and sends info+ lines every 5 s unless the user turns off "Enviar registros ao servidor" (`Settings.sendLogs`).
